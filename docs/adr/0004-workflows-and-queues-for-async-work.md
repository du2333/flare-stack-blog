# Use Queues for async delivery work

Flare Stack Blog uses Queues for delivery work that benefits from retry, such as email and webhooks. Publishing a Post does not use a queue for that write path. Creating a Comment does not wait on a queue: the Comment is public immediately, and reply notifications go on the Queue. The same publish request writes the Post Revision, replaces the Public Content Snapshot, updates the Search Index, and updates the Public Cache. Code highlighting in that snapshot is produced by the Admin editor, or kept from the previous snapshot when the code is unchanged; the Worker does not highlight. That sequence is idempotent: if any step fails, the Admin publishes again.
