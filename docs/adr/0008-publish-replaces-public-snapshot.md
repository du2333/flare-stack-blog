# Publish replaces the Public Content Snapshot; do not schedule publication

The public site reads only the Public Content Snapshot, which holds the public title, summary, slug, content, tags, publication date, and pin state. Reading time is derived from content when rendering and is not stored. Publishing replaces that snapshot from the Post the Admin is editing; autosave does not. Unpublishing discards the snapshot. Draft versus published is the outcome of those two actions, not a separate status the Admin toggles and later syncs. A Published Post is public immediately, so there is no scheduled publication. The publication date is for display and listing order, taken from server time on first publish if missing, and it cannot be in the future. A Post Revision is created when publishing, and again immediately before restoring another revision so unpublished edits are not lost. Autosave does not create a Post Revision. Restoring a Post Revision updates only the Post the Admin is editing. Changing the slug and publishing again leaves the old public slug unreachable. There is no auto-snapshot queue or workflow.
