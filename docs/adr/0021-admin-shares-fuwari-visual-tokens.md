# Admin shares Fuwari visual tokens

Public pages remain the only presentation (Fuwari). Admin stays a workbench layout and does not copy the public navbar, banner, or 75rem column. Admin and public use one stylesheet, so color, controls, type, onload animation, and toasts stay in sync, and Site Config hue applies to both. Warning, danger, and success keep fixed hues (85, 25, 145) and reuse the same lightness/chroma recipes as Fuwari controls, so they stay yellow/red/green as Site Config hue changes. This supersedes the sentence in ADR 0012 that Admin keeps its own stylesheet, and does not restore a Theme Contract.

Amended by [ADR 0038](./0038-themes-are-built-in-shells-chosen-at-runtime.md): Fuwari is now one Theme among several, and the Admin reads a base layer of the variables that no Theme overrides.

Amended 2026-11-11: the Admin still shares the stylesheet and the controls with the public side, but no longer the hue. Once the personalize page let the owner drag the primary hue live, the workbench's own navigation, buttons and surfaces changed colour with it, and on the light scheme the white text on the primary button reached only about 2.66:1. The Admin now has fixed values of its own, defined once in `src/styles/admin-variables.css` under the same `--fuwari-*` names: warm neutral paper and ink, and a fixed teal accent for primary buttons, links, selected states and focus rings, in both Colour Schemes, with the contrast of text and accent checked. Large tinted fills give way to plain surfaces with a hairline, and radii are a little tighter. Success, warning and danger keep the fixed hues above. Public pages, the embedded blog preview on the personalize page, the post editor's content typography and notification emails are unchanged, and a test checks that no variable the Admin reads derives from the hue.

Amended again 2026-11-11 (spec #298): the accent is ink, with no hue: `#2b2722` under `#fdfbf7` text in the light Colour Scheme, `#ece6da` under `#1f1b17` in the dark one, for primary buttons, selected states, switches, focus rings and progress; links are ink with an underline. This replaces the teal above, and success, warning and danger are now the only colours in the Admin with a hue. The shell changes with it: the sidebar lies on the page colour and the content is one plain surface beside it, with a hairline between them and no floating cards, radii or outer margin; every page except the post editor and its history uses one page frame (`AdminPage`, `docs/admin-page-frame.md`), and the type scale and density it shares are variables in `src/styles/admin-variables.css`. `admin-variables.test` computes the contrast of the ink accent from those values.

Amended 2026-11-12 (spec #304): the Admin is redesigned on a neutral grey canvas (`#f3f3f1`, dark `#0d0d0f`) with white cards (`#ffffff`, dark `#17171a`), a hairline and a very light shadow, replacing the warm paper. Primary buttons stay ink (`#16161a` under white, dark `#ededf0` under `#121214`), but the accent is no longer ink: it is a flame orange, `#f26522` in light and `#ff8a4c` in dark, with a darker `#c2470d` (dark `#ff9d6b`) for accent text, used only where something asks for attention (the current navigation item's icon, pending counts, drafts, the charts, focus rings). It is not an option. The design variables are `--admin-*` (`canvas`, `surface`, `sunken`, `line`, `line-strong`, `fg`, `fg-2`, `fg-3`, `hover`, `press`, `ink`, `on-ink`, `accent`, `accent-text`, `accent-soft`, the three shadows, `radius-card` and the two easings) in `src/styles/admin-variables.css`, and the `--fuwari-*` values the shared controls read now come from them; the type face is Geist with the system's Chinese face, loaded for the Admin only. Success, warning and danger keep their fixed hues. The shell puts the navigation and the page on one canvas, with the current item on a sliding white pill, a command palette on Ctrl/⌘ K, and a modal drawer below 1024px; the collapsed rail is gone. `admin-variables.test` computes the contrast from the new values and lists the pairs that fall short of WCAG: the faint text (`--admin-fg-3`, about 3:1 on a card) and, in light, the accent on the canvas (2.8:1 as a focus ring, 4.5:1 as text).
